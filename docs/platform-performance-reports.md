# 标注日报与周绩效

平台新增“首次提交增量台账”。它与原来的人员统计分开：原统计继续用于耗时、BBox 等兼容视图；日报和周绩效只读取成功提交事件。

## 计数规则

当前管理平台记录的是 Part 级数量，没有逐张图片的唯一 ID 或标注工具的保存回执。本功能由标注员确认实际成功提交的累计量，不能自动扫描并验证每张图。累计数量必须始终指向同一个固定 Part；不能把同一批图片拆成新的 Part 再报量。若需要从标注工具自动取数，应继续对接该工具的逐图提交接口。

- 只有标注员明确点击“提交当日进度”或“提交完成”后才计入。
- 进度填写的是 Part 的累计成功提交量，不是当天新增量。系统用累计量减去这个 Part 之前已计入的数量，得到本次新增量。
- 一个 Part 可跨天拆分。例如 60/100 后提交，次日完成到 100，日报分别是 60 和 40。
- 首次完成提交后会冻结绩效高水位；审核返工和再次提交为 0，不会因修改总量而增加完成量。
- Part 退还后由其他标注员继续完成时，台账保留每次提交人的归属。
- 报表按北京时间和提交时间统计，不按审核时间统计。
- 周报周期为周二 00:00 至下周二 00:00（页面显示为周二至周一）。工作日筛选默认排除周六、周日；没有配置法定节假日或调休表。

## 使用步骤

1. 标注员在 Part 中修改累计进度后点击“提交当日进度”；全部完成时点击“提交完成”。仅修改输入框不会产生绩效事件。
2. 管理员打开“日报与周绩效”，选择日报或周绩效和日期。
3. 按人员复制项目列、实际完成数量，粘贴到钉钉普通在线表格。平台没有钉钉文档写入权限，因此最后一步仍需人工粘贴。
4. 日报模板的目标量、任务评级、情况记录，以及周报模板的计划量、是否完成、总得分、绩效评级和备注不由系统猜测，继续人工填写。

请在实际完成当天提交，平台以按钮成功提交的服务器时间记账，不能还原迟报的实际完成日期。退还 Part 前先提交自己的累计进度，剩余量才会正确归到后续接手人员。未知图片总数（总量为 0）时，最终提交使用已填写的累计进度；建议在派发 Part 前录入真实总量。

日报对应 `李欣 日报.xlsx` 的 D 列“当日完成的标注项目名称”、F 列“实际完成数量”；周报对应 `实习生周绩效报告.xlsx` 的 A—D 列（姓名、起止时间、数据集名称）及 F 列“周完成总量”。请只粘贴这些列，避免覆盖 E 列的计划量和后续评价列。复制的姓名是普通文本，钉钉的 @人员关联如需保留，应只复制项目和完成量。

周报模板 H 列存在类似 `=IFERROR(F2:F1000/E2:E1000," ")` 的多行范围公式。源文件没有被修改；请在钉钉中核实该公式是否产生预期结果。逐行完成率通常应使用同一行的 F/E（计划量为 0 或空时留空），不应据此推导总得分或评级。

## 历史数据

启用该功能前的 Part 只有当前累计量，缺少首次提交日期和分批提交过程。迁移会保留它们作为“旧记录”来阻止返工重复计数，但不会把它们伪造为某一天的完成量。报表会显示启用时间和旧记录数量；启用时间之前的周期可能不完整。

## 接口

- `POST /api/tasks/{task_id}/parts/{part_id}/submit-progress`：提交累计进度。
- `GET /api/admin/production-report?period=day|week&date=YYYY-MM-DD&workdays_only=true|false`：读取日报/周绩效事件报告。
- `/reports`：管理员复制报表页面。
