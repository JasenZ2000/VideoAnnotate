# 轨迹融合方法说明

跟踪器会分别生成 `forward_tracks` 和 `backward_tracks`。轨迹融合阶段负责把这些轨迹片段组合成最终轨迹组件，再交给 `build_final_tracks` 完成目标框融合、短轨迹过滤和平滑。

## 基础方法

| 方法 | 配置值 | 逻辑 | 优点 | 主要问题 |
| --- | --- | --- | --- | --- |
| 双向互选 IoU | `bidirectional_iou` | 正向和反向轨迹片段只有在重叠帧足够、平均 IoU 达标、首尾中心距离不过大并且互为最佳匹配时才会合并。未合并的正向和反向轨迹都会单独进入结果。 | 策略保守，不容易把不同目标强行连接；反向轨迹能够补回正向跟踪漏掉的目标。 | 互选失败或阈值过严时，重复的反向轨迹仍会保留，可能为同一目标产生重复 ID；无法修复重叠帧不足的前后向断轨。 |

## 可选方法

| 方法 | 配置值 | 逻辑 | 适用问题 | 可能代价 |
| --- | --- | --- | --- | --- |
| 仅使用正向轨迹 | `forward_only` | 完全忽略反向轨迹，每条正向轨迹片段单独形成最终组件。 | 建立清晰基线并避免所有反向重复 ID；适合反向结果明显较差的情况。 | 失去反向补漏能力，正向断轨不会被修复。 |
| 仅使用反向轨迹 | `backward_only` | 完全忽略正向轨迹，每条反向轨迹片段单独形成最终组件。 | 用作调试对照，检查反向跟踪是否比正向跟踪更稳定。 | 正常生产中很少作为默认策略。 |
| 正向主导互选 | `bidirectional_iou_forward_primary` | 以正向轨迹为主，只合并互选成功的反向轨迹，丢弃未匹配的反向轨迹。 | 减少反向重复轨迹，同时保留部分双向目标框融合和平滑收益。 | 反向跟踪独有的真实目标会被丢弃。 |
| 正向主导并保留唯一反向轨迹 | `bidirectional_iou_forward_unique` | 以正向轨迹为主，互选成功时合并；未互选但与任一正向轨迹高度重叠的反向轨迹视为重复并丢弃；与所有正向轨迹都明显不同的反向轨迹则保留。 | 在减少重复 ID 的同时保留反向补漏能力，通常比默认方法更均衡。 | 如果两个相邻目标长时间高度重叠，可能误丢真实反向轨迹。 |
| 全兼容合并 | `bidirectional_iou_all_pairs` | 不要求互为最佳匹配，只要前后向轨迹对满足 IoU 和中心距离约束，就合并到同一组件。 | 更积极地合并轨迹碎片，减少同一目标出现多个 ID。 | 拥挤场景下更容易发生串轨。 |
| 双向互选并去重 | `bidirectional_iou_nms` | 先执行 `bidirectional_iou`，再按组件质量保留高质量组件，移除与已保留组件高度重叠的重复组件。 | 在较少改变旧行为的情况下，处理默认方法产生的反向重复 ID。 | 两个真实目标长时间重叠时，可能误删较短或质量较低的轨迹。 |

## 推荐尝试顺序

| 场景 | 建议方法 |
| --- | --- |
| 需要确认问题是否来自反向融合 | `forward_only` |
| 默认方法产生明显重复 ID | `bidirectional_iou_forward_unique` 或 `bidirectional_iou_nms` |
| 默认方法断轨较多且目标不拥挤 | `bidirectional_iou_all_pairs` |
| 反向结果整体不可信 | `bidirectional_iou_forward_primary` 或 `forward_only` |
| 希望最大程度保持旧行为并减少重复 | `bidirectional_iou_nms` |

## 配置示例

```json
{
  "fusion": {
    "method": "bidirectional_iou_forward_unique",
    "iou_fuse": 0.5,
    "min_track_len": 10,
    "smooth_window": 5
  }
}
```
